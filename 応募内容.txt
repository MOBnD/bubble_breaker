プログラム動作の説明（作品の遊び方）
APIキーを設定し、気になるテーマを入力して「宇宙へダイブ」を押すと、テーマを検索して情報を集め、関連する話題を大小のバブルで表した世界を作ります。バブルをクリックするとその話題へ入り、マウスホイールで階層を深掘りしたり、前の階層へ戻ったりできます。3D表示ではW・A・S・Dで前後左右、Q・Eで上下に移動し、Shiftを押すと速く移動できます。設定から2D表示にも切り替えられます。バブルの詳しい画面では、概要・歴史・情報源・賛否それぞれの視点を確認でき、出典リンクから根拠を確かめられます。探索した世界は保存され、あとから再開できます。


プログラムのソースコードの抜粋と意図（応募用の5案）

※応募欄は「3か所」とありますが、選べるように5案を用意しました。特に1・2・5は、実装上の工夫がコードから伝わりやすい案です。ファイル名と行番号は現在のソースに基づいています。

1. カテゴリ階層の親子関係が破綻しないようにした方法

抜粋：src/js/api.js 724～756行付近
    const roots = groups.filter(group => group.parentId === null);
    if (roots.length !== 1) throw new Error('親カテゴリは1つだけ必要です');
    const requireUniqueChild = (parentGroup, bubble, level) => {
        if (!bubble.childId) throw new Error(`${level}のバブルに下位カテゴリ接続がありません`);
        const child = db[bubble.childId];
        if (child.level !== (level === '親カテゴリ' ? 'central' : 'leaf')) {
            throw new Error(`${level}のchildIdが一つ下のカテゴリではありません`);
        }
        if (child.parentId !== parentGroup.id) throw new Error(`${level}のchildIdの親カテゴリが不正です`);
        if (referencedIds.has(child.id)) throw new Error(`${level}の下位カテゴリが重複しています`);
        referencedIds.add(child.id);
        return child;
    };

接続先を親バブルIDから正規化する箇所（src/js/api.js 675～677行）
    group.parentId = parentGroup.id;
    group.parentBubbleId = parentBubble.id;
    childGroupsByParentBubble.set(parentBubble.id, group);

意図：AIが生成したデータを、そのまま画面に表示せず、親カテゴリroot・中央カテゴリcentral・下位カテゴリleafの順序とIDのつながりを検査します。親バブルに子カテゴリが一つだけ対応すること、親子の階層が一段ずつ進むこと、孤立したカテゴリが残らないことを確認します。親カテゴリIDだけでなく、親バブルIDも使って接続先を照合するため、「どのカテゴリの、どのバブルの下位なのか」を特定できます。条件を満たさないデータはエラーとして扱い、不正な階層が探索画面に出るのを防ぐ設計です。

3. 厳密な要件定義書をCodexに渡して開発したこと

参照：BubbleBreaker仕様書.md、BubbleBreaker仕様書.xlsx、src/js/api.js 1393～1404行および1427～1432行付近
rootからcentralを作る箇所：
    const rootResult = await requestRootGroup(activeAnalysisInput, generationController.signal);
    const root = rootResult.group;
    const centralResults = await runWithConcurrency(root.bubbles, 3, rootBubble => requestCentralGroup(
        activeAnalysisInput,
        root,
        rootBubble,
        rootBubble.id === rootResult.entryRootBubbleId,
        rootResult.explorationAxes,
        generationController.signal
    ));

生成した階層をまとめて検証する箇所：
    const mergedGroups = [root, ...centralGroups, ...leafGroups];
    const universe = normalizeGeneratedUniverse({
        groups: mergedGroups,
        entryGroupId: entryResult.group.id,
        entryBubbleId: entryResult.entryBubbleId
    });

説明：私は、作品の目的や画面構成だけでなく、カテゴリの階層、画面間の移動、入力に対する動きなどを仕様書に整理し、Codexに渡して実装を依頼しました。たとえば、話題をroot・central・leafの順に組み立て、親バブルと子カテゴリの対応を保つ要件を明確にしています。コードでは、rootを確定してから各バブルのcentralを作り、その後に各centralのバブルからleafを作る順序として実装し、最後に全体を検証します。仕様を文章で具体化することで、生成されたコードを「希望した動作や構造になっているか」という観点で確かめられるようにしました。

※Codexを使ったこと自体はプログラム実行時の機能ではなく、開発方法についての説明です。

4. 画像が少ない画面に、検索で見つけた画像をURLから表示する方法

抜粋：src/js/research.js 149～163行、179～199行付近

    }]

    const sourceWebsiteUrl = safeHttpsUrl(result.source_website_url);
    if (!imageUrl || !sourceWebsiteUrl || seen.has(imageUrl)) return;

抜粋：src/js/scene.js 2693～2702行付近
    imageNode.src = image.thumbnailUrl || image.imageUrl;

意図：画像をプログラム内に固定で埋め込まず、テーマや分析カードに合わせたWeb画像検索から画像URLと出典ページURLを受け取ります。HTTPSのURLだけを採用し、出典がない画像や重複画像を除外してから、HTML画像要素のsrcにURLを設定して表示します。詳細画面には出典ページへのリンクも付けています（src/js/scene.js 2778～2802行）。画像の読み込みに失敗したときは表示を隠す、またはサムネイルから元画像へ切り替える処理もあり、画像がない場合に画面が崩れにくいようにしています。画像そのものを配布ファイルに保存する方式ではなく、表示時に外部URLから読み込む方式です。

説明：話題について一度だけ自由回答を求めるのではなく、賛成を支える情報、反証や批判、一次資料、定義や背景という4つの検索意図に分けて調べます。検索結果は決めたJSON形式で受け取り、URL・発信元・公開日・関連抜粋・検証できる主張候補として整理します。

次に、src/js/research.js 262～322行付近で、モデルが返したURLが実際のWeb検索結果に含まれているかを照合し、未確認のURLを除外します。同じURLや本文の重複をまとめ、同一ドメインや転載関係のある情報源を独立した根拠として二重に数えないようにグループ化します。

さらに、334～343行付近で主張を細かく分け、各情報源が支持・反証・不明のどれに当たるかを比較します。366～402行付近では、独立した情報源の数、支持と反証の照合、一次資料の有無、検索意図の網羅度、抜粋や公開日の有無などから根拠の充実度を計算します。この値は主張が真実である確率ではなく、集めた根拠がどの程度そろっているかを示すための指標です。

最後に、549～565行付近で検証済みの情報だけを分析文へまとめ、各説明に対応する出典IDも返すようにしています。検索、出典確認、主張の比較、分析文の作成を段階に分けることで、根拠のない補足や一方の意見だけに寄った要約を減らす意図があります。


苦労した点や改善したい点（200字以内）
テーマを変えて何度も探索し、バブルを選んで階層を上下したとき、親子関係とズームの流れが意図どおりか確認しました。ずれた時は、曖昧な指示を親子の対応や移動前後の見え方まで具体化し、仕様書とプロンプトを直して再確認しました。今後は3階層に限らず、全バブル群が一つの3D空間につながり、上下左右へ自由に進める冒険的な探索にしたいです。


アピールポイント（200字以内）
フィルターバブルの外に広がる世界を、3Dの宇宙をズームイン・ズームアウトして探検できるのが本作の魅力です。バブルを深くたどるほど異なる視点に出会い、広く見渡すと、自分が知っていた世界の小ささに気づく。思わずぞっとするような感覚的な体験を目指しました。
