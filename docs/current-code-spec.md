# BubbleBreaker 現行コード仕様書

この文書は、既存の仕様書ではなく、現在の `src/` とビルドスクリプトの実装から再構成した現行仕様書です。実装と内容が異なる場合は、コードとテストを優先します。

## 1. 目的と実行形態

BubbleBreakerは、入力された意見を起点に、Web Searchで調査したカテゴリをThree.jsの宇宙として表示するブラウザプロトタイプです。利用者は、入力意見を含むバブルから、親・中央・下位カテゴリを順番に探索し、個別バブルの分析を閲覧します。

開発時のソースはHTML、CSS、JavaScriptに分割されています。`npm run build` はこれらを結合し、APIキーを含めずモデル名だけを設定した `dist/bb_proto4.html` を生成します。実行時は生成された単一HTMLをWebサーバー経由で開きます。外部依存はTailwind CDN、Three.js CDN、OpenAI Responses API、BGMファイルです。

## 2. ソース構成と起動

- `src/index.html`: CDN、画面DOM、ローカルスクリプトの読み込み順を定義するHTMLシェル
- `src/styles.css`: 画面レイヤー、パネル、ラベル、遷移、スクロールバーのスタイル
- `src/js/data.js`: 固定DB、固定フォールバック、現在使用する `activeDB`
- `src/js/api.js`: OpenAIの階層生成、応答の解析・正規化・検証、バブル分析
- `src/js/state.js`: 画面状態、探索モード、ダイブ状態、API入力状態
- `src/js/audio.js`: 効果音、BGM、音量、トラック遷移
- `src/js/navigation.js`: `switchScreen` による画面切り替え
- `src/js/scene.js`: Three.js、宇宙背景、バブル、カメラ、カテゴリ遷移、分析表示
- `src/js/events.js`: クリック、入力確定、ボタン、ホイール、設定変更
- `src/js/animation.js`: ダイブ、カテゴリ遷移、カメラ補間、背景・バブル更新、描画ループ
- `scripts/build.mjs`: 分割ソースを `dist/bb_proto4.html` にインライン化し、APIキーを除去
- `scripts/check-visual-navigation.mjs`: 銀河・ブラックホール・ズーム操作の視覚仕様に関するソース不変条件を検査

```powershell
npm run build
npm run check
npm run check:visual
npm test
```

## 3. 画面と画面遷移

画面状態は `INPUT`、`GROUP`、`SINGLE`、`ANALYSIS`、`DETAIL` の5種類です。

1. `INPUT`: 意見を入力してダイブを開始する。
2. `GROUP`: 現在のバブル群、カテゴリ名、カテゴリ型、構成バブル、占有率を表示する。
3. `SINGLE`: 選択したバブルの説明、占有率、偏り度、下位カテゴリへの導線を表示する。
4. `ANALYSIS`: 選択バブルの概要、形成史、構成層・情報源、内外評価の4カードを表示する。
5. `DETAIL`: 選択した分析カードの要約、インサイト、メトリクス、出典を表示する。

バブル群ではバブルのクリックで個別画面へ進みます。探索者モードでは、子カテゴリを持つバブルの選択で直接その子カテゴリへ進みます。上方向ホイールは子カテゴリへの移動、下方向ホイールは個別画面・分析画面・親カテゴリへの復帰に使用します。バブル群から親へ戻る場合は、まず現在群全体が見える俯瞰状態を作り、追加の下方向操作で親へ移動します。

バブル群でバブルを選択していない場合もOrbitControlsのズームとドラッグを利用できます。ズームイン操作でカメラが前方の最寄りバブルへ半径に応じた近接距離まで入った場合だけ、そのバブルの個別画面へ自動遷移します。ドラッグやズームアウトでは個別画面へ遷移しません。rootを含む全カテゴリでカメラのズームイン・ズームアウトを利用でき、親カテゴリがない場合は階層を変えずカメラだけを動かします。

## 4. データモデルと階層規則

カテゴリは次の3階層です。

```text
root   親カテゴリ
  └ central  中央カテゴリ
       └ leaf  下位カテゴリ
```

各カテゴリは、`id`、`title`、`type`、`parentId`、`parentBubbleId`、`desc`、`bubbles` を持ちます。各バブルは、`id`、`name`、`size`、`color`、`htmlColor`、`pos`、`childId`、`desc`、`analysis`、`sources` などを持ちます。

- rootの `parentId` と `parentBubbleId` は `null`
- centralの `parentId` はrootのID
- leafの `parentId` はcentralのID
- 子カテゴリの `parentBubbleId` は直上カテゴリに実在する親バブルID
- 親バブルの `childId` は対応する子カテゴリID
- APIの各段階でモデルが返すIDは段階内の検証にのみ使い、統合前にクライアントがroot・central・leafの枝に基づく一意な内部IDへ正規化する
- 親カテゴリの各バブルには固有の中央カテゴリを対応付ける
- 中央カテゴリの各バブルには固有の下位カテゴリを対応付ける
- 入力意見の経路だけを特別扱いせず、全経路を同じ具体性・深度で生成する
- 参照先が不正な宣言値でも、`parentBubbleId` などから一意に解決できる場合は実在IDへ正規化する
- 親バブルが解決できない、子カテゴリを共有する、階層が不一致などの場合は不正として扱う

API生成に失敗した場合は、テンプレートで不足カテゴリを補完せず、検証済みの固定DBへフォールバックします。

## 5. API生成と分析

意見確定後、階層生成は次の段階で実行されます。

1. OpenAI Responses APIの `web_search` とStructured Outputsでrootカテゴリだけを生成・確定する。この応答で入力意見が属するrootバブルのIDも1つ確定する。
2. 確定したrootの各バブルを親コンテキストとして、centralカテゴリを1つずつ生成する。入力意見のroot枝だけはentryBubbleIdを必須にし、それ以外の枝ではentryBubbleIdを禁止する。siblingsだけを最大3件まで並列化する。
3. 確定した全centralの各バブルを親コンテキストとして、leafカテゴリを1つずつ生成する。ここでもsiblingsだけを最大3件まで並列化する。
4. クライアント側で各段階のlevel、parentId、parentBubbleId、childId、対応数、バブル数を検証してから全体を正規化する。
5. 失敗した段階だけを再試行し、最終的に不完全ならテンプレート補完をせず固定DBへフォールバックする。

入力確定後はダイブ演出とAPI処理を並行します。`loadGroup` でバブル群へ入った時点で、その群の全バブルについて分析要求を開始します。分析要求はバブル単位で重複排除され、最大同時実行数を制限します。分析失敗時もカテゴリ探索は継続し、既定分析を表示できます。

分析は概要、形成史、構成層・情報源、内外評価を持ちます。各項目は要約、インサイト、メトリクスを含み、利用可能なWeb出典を保持します。

## 6. Three.js空間

Three.jsのシーンには、固定シードで生成される星、6形状以上の独立した銀河、最遠景のNGC 3324写真ドーム、銀河外の恒星系、惑星、彗星、小惑星帯、頭部・尾部・残光粒子を持つ流れ星が複数距離に配置されます。単独星は銀河位置まで届く球状ボリュームへ配置し、円形と星芒形を混在させます。各銀河Groupのローカル中心にブラックホールを1つだけ置き、銀河内には形状形成用の恒星だけを配置します。惑星・小惑星帯・彗星を持つ恒星系は銀河外へ分離し、その一部をバブル群の近距離へ置きます。NGC 3324以外の星雲は生成しません。カテゴリバブルは同じワールド空間上に配置されますが、クリック判定は現在のバブルだけを対象とします。カテゴリ移動時とブラックホール接触時には、60個の銀河を個別に最低距離付きランダム配置へ再配置します。

単独星、銀河、恒星系、流れ星は球状配置で、初期カメラの正面だけでなく背面・上下・左右を含む360度へ分散します。銀河は半径約7,600〜11,800の広い球殻へ最低距離を保って個別配置し、恒星系は約1,200〜12,500へ分散します。NGC 3324は半径約70,000の独立した内向きドームで全方向を覆います。背景全体、銀河、個別恒星系、NGC 3324はそれぞれ異なる遅さで連続回転します。

背景はPoints、InstancedMesh、簡易ジオメトリ、NGC 3324の高解像度写真テクスチャを中心に構成します。単独星は背景要素の約2割に抑え、銀河内の恒星・銀河外恒星系・NGC 3324写真・銀河構造を増やします。単独星と銀河内恒星はサイズと光度を大きく変え、銀河ごとに恒星、ダスト、コア、降着円盤、光子リングの色プロファイルを固定します。NGC 3324は実行時に左右端をクロスフェードしたCanvasTextureへ変換し、半径70,000の内向き球面へ貼り付けます。ロード中は設定した速度と経由天体数に応じ、実際の銀河中心または恒星系をアンカーにした円弧スイングバイ航路を進みます。API読み込みが完了した時点で現在位置から目的ブラックホールへのUターン航路へ切り替えます。集中線レイヤーは使わず、設定可能なフレーム残像だけで速度感を表現します。通常時は背景天体をゆっくり回転・公転させます。

銀河形状は楕円、球状、渦巻、棒渦巻、レンズ状、不規則を使い分けます。ブラックホールは不透明な黒い事象の地平面と、その外側の光子リング・降着円盤で描画し、ワイヤーフレーム球は使いません。入力確定後のダイブは、設定した速度で0〜30個（初期5個）の経由天体をスイングバイし、API読み込み完了後に経由地を終了して目的ブラックホールへUターンします。最後の経由地またはUターン後の最終航路では目的ブラックホールを画面中央へ向けます。ブラックホール手前で1秒停止した後、FOVを設定値から加速度的に狭めながら事象の地平面へ突入します。突入後は約0.2秒の光点表示と約1.28秒の高速ズームで、約1.5秒以内に次のバブル群へ到達します。

バブル群のカテゴリ移動では、現在のワールドオフセットとスケールを保持します。子カテゴリへ進む時は親バブル位置を基準にズームインし、親カテゴリへ戻る時はナビゲーションスタックから以前の位置を復元します。

## 7. UI、音声、永続設定

画面全体は固定レイヤーで構成され、ページ全体はスクロールしません。右パネル内の長い構成リストだけがスクロールします。音声ON/OFF、BGM、音量、曲、曲の自動送り、カテゴリ移動時の曲変更、探索者モード、FOV、航行速度、経由天体数、航行モーションブラー、ブラー強度はlocalStorageに保存されます。FOVは35〜100度、航行速度は0.25〜3.0倍、経由天体数は0〜30個（初期5個）、ブラー強度は0〜100（初期50）です。新規環境のデフォルトBGMはエッジワース・カイパーベルトで、旧日本語ファイル名の保存値はASCIIファイル名へ移行します。BGMの読み込み可能状態とエラーはConsoleへ記録します。

## 8. エラー処理とセキュリティ

APIのタイムアウト、ネットワークエラー、HTTPエラー、JSON解析失敗、階層不正、バブル数不正をConsoleへ記録します。APIキーやAuthorizationヘッダーはログに出しません。APIキーは起動後に画面入力し、ページのメモリ内だけで保持します。ただしブラウザから直接APIを呼び出すため、入力したキーを実行環境から完全には隠せません。本番で共有キーを使う場合はバックエンドプロキシを使用します。

## 9. 検証基準

- `npm run check` が成功する
- `npm test` が階層正規化、欠落、重複、固定フォールバック、分析要求を検証できる
- `npm run build` が単一HTMLを生成する
- 生成HTMLの上下左右に白い余白がない
- 右パネルの文字が宇宙背景上で読める
- バブル群の全体表示後、追加操作でのみ親カテゴリへ移動する
- API生成、固定DB、分析遅延、画面リサイズのいずれでもUIが破綻しない
