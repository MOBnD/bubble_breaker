# BubbleBreaker v2 — Codex Handoff / 要件定義

> **用途:** 別アカウントのCodexに、そのまま新規プロジェクト仕様として渡すための自己完結型ドキュメント。
>
> **重要:** この文書は「既存BubbleBreakerの修正指示」ではなく、**新しいUXコンセプトに基づく再設計プロジェクト**のベースライン仕様である。

---

## 0. プロジェクト定義

### 0.1 プロジェクト名

**BubbleBreaker v2 — Information Adventure**

### 0.2 サービス一文定義

> **BubbleBreakerは、ユーザー自身の興味関心によって形成された情報の偏りから意図的に外へ出て、未知の情報や意外なつながりを「冒険」として発見する情報探索サービス。**

### 0.3 最重要UX原則

> **常に「この先には何があるんだろう？」という好奇心を残し、次の一歩へ進みたくなる状態を作る。**

### 0.4 解決したい課題

現代のインターネットでは、検索・閲覧・クリック・いいね・広告などの履歴から、ユーザーが好みそうな情報が優先表示されやすい。その結果、ユーザーは自分の興味に近い情報へ集中し、自分と異なる分野・視点・情報に出会う機会を失いやすい。

BubbleBreakerは、この問題を「注意喚起の記事を読むこと」で解決するのではなく、**探索体験そのものを変えること**で扱う。

---

# 1. プロダクトビジョン

## 1.1 体験の変換

### 従来型Web

`検索 → 結果 → 閲覧 → 終了`

### BubbleBreaker

`出発 → 探索 → 予感 → 発見 → 意外な接続 → 理解 → 世界が広がる → 次の未知へ`

## 1.2 ユーザーに残したい感情

1. **予感:** 「何かありそう」
2. **好奇心:** 「何だろう？」
3. **探索欲:** 「行ってみたい」
4. **発見:** 「え、こんなのあるんだ！」
5. **接続:** 「これとこれがつながるの？」
6. **アハ体験:** 「なるほど、そういうことか！」
7. **継続意欲:** 「この先には何があるんだろう？」

## 1.3 最重要成功条件

ユーザーがサービスを閉じたとき、

> 「情報をいくつか読んだ」

ではなく、

> **「自分の知らない世界を冒険して、新しい発見をした」**

と感じること。

---

# 2. 体験原則

## 2.1 「冒険」は見た目ではなく構造

単にファンタジー背景を追加するだけでは不可。

以下を**機能要件・画面要件・演出要件にまたがる共通原則**とする。

- すべての主要画面に未探索要素を残す
- 次の探索先を必ず1つ以上示唆する
- すべてを最初から見せない
- 意外な情報遷移を意図的に発生させる
- ただし完全ランダムにはしない
- 「なぜこの情報へ来たのか」を後から理解できるようにする
- 発見によって世界が実際に広がったように感じさせる
- 数値報酬より「未知を発見したこと」自体を報酬にする

## 2.2 避ける体験

- カテゴリツリーに背景画像を載せただけのUI
- ニュースサイト型カード一覧
- 無限スクロール型おすすめ
- 「ランダム記事を出すだけ」のセレンディピティ
- XP・ランキングだけで探索を促すゲーミフィケーション
- ファンタジー要素が情報探索より前面に出ること
- 最初から全世界が見えること

---

# 3. 世界観 / 情報構造

## 3.1 基本設定

インターネット上の情報世界を巨大な異世界として表現する。
ユーザーはその世界を旅する**冒険者**。

ただし、ゲームを遊ぶことが目的ではない。ファンタジーは「情報との出会い」を体験可能にするためのメタファーである。

## 3.2 情報と世界の対応

| 情報モデル | 世界表現 |
|---|---|
| 大カテゴリ | 王国 / 大都市 / 大陸 |
| 中カテゴリ | 都市 / 地域 |
| 小テーマ | 村 / 集落 |
| 深掘り | 洞窟 / 遺跡 / 地下世界 |
| 異分野 | 遠方の大陸 |
| 情報間の関連 | 道 / 橋 / 海路 / ゲート |
| 未知の情報 | 霧の領域 |
| 新しい発見 | 新天地の開拓 |
| 探索履歴 | 冒険記 |
| 意外な関連 | 秘密の道 / 隠しルート |

## 3.3 世界地図

現在のカテゴリツリーはバックエンドの情報構造として保持する。
ユーザーにはツリーそのものではなく、**世界地図として見せる**。

### 地図の基本要素

- 現在地
- 探索済み領域
- 未探索領域
- 道
- 分岐
- 遠景のランドマーク
- 発見イベント地点
- 「まだ到達できない」場所

### 霧

霧は単なる非表示ではなく、**未だ知らない情報が存在することを示すUI**。

完全な空白ではなく、遠景に「塔」「山」「光」「島」などの存在を匂わせる。

# 4. コア機能

## 4.1 出発

ユーザーが探索開始地点を決める。

### 出発方法

- **興味から出発:** 自分でテーマを選ぶ
- **偶然に任せる:** 現在地近辺の意外な領域へ
- **未知へ飛ぶ:** 興味から大きく離れた領域へ

## 4.2 探索

世界地図上を移動し、地点・道・建物・ランドマークなどを操作する。

## 4.3 発見

新しいテーマに到達したとき、単なる記事一覧ではなく「発見イベント」を発生させる。

## 4.4 なぜここに来たのか

情報遷移の理由を可視化する。

例:

`ゲーム → 音楽 → 感情 → 心理学 → 行動経済学`

ユーザーが「偶然なのに納得できる」状態を作る。

## 4.5 分岐

発見後は必ず複数の進み方を提示する。

- **深く潜る:** 同じテーマを深掘り
- **横へ進む:** 近すぎず遠すぎない異分野へ
- **未踏の地へ:** 興味領域から大きく離れた領域へ

## 4.6 冒険記

閲覧履歴ではなく、「自分が歩いた情報世界」を記録する。

保存対象:

- 訪れた領域
- 発見した地点
- 情報間の経路
- 意外なつながり
- 代表的な発見
- 自分の探索領域の広がり

---

# 5. 情報探索ロジック

## 5.1 情報距離

テーマ間に「距離」を持たせる。

- 距離0〜1: ほぼ同じ領域
- 距離2〜3: 近接分野
- 距離4〜5: 異分野
- 距離6+: 大きく離れた未知領域

※ 数値は初期実装のたたき台であり、アルゴリズム実装時に調整可能。

## 5.2 セレンディピティ段階

### LEVEL 1 — 隣の世界

例: `ゲーム → 音楽`

### LEVEL 2 — 遠い世界

例: `ゲーム → 心理学`

### LEVEL 3 — 異世界

例: `ゲーム → 農業`

### LEVEL 4 — 意外な接続

例:

`ゲーム → 群衆 → 人間行動 → 集団心理 → 災害避難`

LEVEL 4をBubbleBreakerらしい代表体験とする。

## 5.3 ランダムではなく「予測不能 + 後から理解可能」

候補生成では少なくとも以下を考慮する。

- 現在テーマとの意味的関連
- ユーザーが既に見たかどうか
- 過去の探索経路
- 情報カテゴリ間距離
- 意外性
- クロスドメイン性

完全ランダムな記事表示は禁止。

# 6. 主要画面

## 6.1 HOME

目的: 探索意欲を作る。

### 必須要素

- 大きな「今日は、どこへ行く？」
- 3つの出発モード
- 世界の遠景
- 未知の存在を示唆するランドマーク
- 前回の冒険を続ける導線

### 原則

ホーム画面をダッシュボード化しない。
「人気」「ランキング」「大量のカード」を主役にしない。

---

## 6.2 WORLD

目的: 情報を世界として探索するBubbleBreakerの中心画面。

### 必須要素

- 現在地
- 霧
- 道 / 分岐
- 発見済み地点
- 未探索地点
- 遠景ランドマーク
- 現在のテーマ名
- 次の探索候補
- 冒険記への導線

---

## 6.3 DISCOVERY

目的: 「アハ体験」を生む。

### 必須要素

1. 新しいテーマ / 土地の名前
2. 短い要約
3. なぜここへ来たか
4. 意外な接続の説明
5. 世界が広がる演出
6. 次の3方向への分岐

---

## 6.4 EXPLORE / BRANCH

目的: 次の移動を決める。

### 選択肢

- 深く潜る
- 横へ進む
- 未踏の地へ

探索を終わらせる「戻る」だけを強調しない。

---

## 6.5 ADVENTURE LOG

目的: 「自分だけの情報世界」を残す。

### 必須要素

- 探索マップ
- 発見履歴
- 発見数
- 開拓領域
- 意外なつながり
- 最初のテーマ
- 現在の探索範囲

---

# 7. 「ゲーム」を選んだユーザーの最初の5分

以下をプロダクトの**標準デモ / UX基準シナリオ**とする。
実装・デザイン・レビュー時はこのシナリオが成立しているか確認する。

## 7.1 0:00 — 出発

### 画面
HOME

### 操作
ユーザーが「興味から出発」を選択。

### 入力
`ゲーム`

### 期待感
「ゲームから一体どこへ行くんだろう？」

### UI
入力確定後、画面の世界地図がゆっくり切り替わり、ゲーム領域を中心とした未知の世界が見える。

---

## 7.2 0:20 — 現在地の到着

### 画面
WORLD

### 表示
中央に「ゲーム」の領域。
周囲には複数の道。

例:

- ゲーム音楽
- ゲームデザイン
- 物語
- 心理学方面の道
- 未知の道

遠方には霧に包まれた大地・塔などを見せる。

### 感情
「ここからどこへ行けるんだろう？」

---

## 7.3 0:40 — 最初の予想外

ユーザーが「未知の道」を選ぶ。

近接カテゴリではなく、ある程度離れたテーマを選択。

例:

`ゲーム → 人間心理`

### 演出
地図上の道が未知の方向へ伸び、霧が一部晴れる。

### 表示
> **新しい領域を発見しました**

> 人間心理

### 目的
最初の「え、ゲームからここに来るの？」を作る。

---

## 7.4 1:00 — 「なぜ？」

DISCOVERY画面。

### 表示

`ゲーム`
↓
`ユーザー体験`
↓
`感情`
↓
`人間心理`

そして短い説明:

> ゲームはプレイヤーの行動・感情・注意を設計するため、人間心理とのつながりがあります。

### 体験
「ランダムで出たわけではない」と理解する。

---

## 7.5 1:20 — 世界が広がる

人間心理の土地を「開拓」する。

地図上に新しい村や道が出現。

例えば:

- 行動経済学
- 集団心理
- 認知科学
- 広告

### 演出
今まで見えなかった4地点が霧の向こうから現れる。

### 感情
「まだこんなにあるのか」

---

## 7.6 1:50 — 2回目のジャンプ

ユーザーが「広告」を選ぶ。

ここからさらに別方向へ。

例:

`広告 → 推薦システム → アルゴリズム`

### 発見
> **あなたが普段見ている「おすすめ」にも、仕組みがあります。**

ここでBubbleBreakerの問題意識と体験が接続する。

---

## 7.7 2:20 — BubbleBreakerそのものに気づく

画面の一部に小さく探索傾向を表示。

> **現在の探索:** ゲーム周辺に集中

> **まだ訪れていない領域:** 社会 / 歴史 / 科学 / 文化 …

そして、

> **「このまま、もっと遠くへ行ってみる？」**

を提示。

ここで初めて「自分の世界が偏っている」ことを体験として気づかせる。

---

## 7.8 2:40 — 未踏の地へ

ユーザーが「未踏の地へ」を選ぶ。

現在のゲーム領域からかなり遠いテーマへ移動。

例:

`ゲーム → 災害避難`

ただし、中間経路は存在させる。

例:

`ゲーム`
→ `群衆シミュレーション`
→ `人間の行動`
→ `災害避難`

### 演出
世界地図が大きくスクロールし、遠い大陸へ移動。

### 期待感
「え、何が始まるの？」

---

## 7.9 3:20 — 大きなアハ体験

### DISCOVERY

> **災害避難**

### 接続

`ゲームの群衆シミュレーション`
↓
`人間の行動モデル`
↓
`避難経路`
↓
`災害避難`

### メッセージ

> ゲームやシミュレーションで使われる「人の動き」を考える技術は、現実の避難計画などを考える際にも関係します。

### 目的
ユーザーが、単に新しい単語を見たのではなく、**異分野のつながりそのものを発見する。**

---

## 7.10 3:50 — 次の未知を見せる

災害避難の領域を開拓すると、さらに遠くに別のランドマークが現れる。

例:

- 建築
- 都市計画
- 公共政策
- 地理

さらに遠くに、まだ説明されていない巨大な塔などを表示。

> **「未踏領域」**

### 目的
大きな発見をした後も体験を終わらせない。

---

## 7.11 4:20 — 冒険記へ

ユーザーが冒険記を開く。

### 表示

```text
今日の冒険

ゲーム
 ↓
人間心理
 ↓
広告
 ↓
アルゴリズム
 ↓
群衆シミュレーション
 ↓
災害避難
```

そして地図上にも、今日歩いた道が光って表示される。

### 感情
「自分はゲームからこんなところまで来たのか」

---

## 7.12 4:40〜5:00 — 次回への引き

冒険記の最後に、まだ開いていない地点を表示。

例:

> **あなたがまだ知らない世界**

`???` `???` `???`

遠くに見えるランドマークを1つだけ強調。

> **「次は、この先へ。」**

ここでセッション終了可能。

### 重要
5分経ったら「完了」とするのではなく、
**5分後にも新しい未知を残す。**

# 8. 5分体験の感情曲線

```text
期待
 ↑
 │       ╭─╮       ╭──╮
 │   ╭───╯ │   ╭───╯  │
 │───╯      ╰───╯      ╰──→ 次の冒険
 │
 └────────────────────────→ 時間
   0   1   2   3   4   5分

期待 → 発見 → 理解 → 再び未知 → 大発見 → 次の未知
```

設計上、感情が一度「理解」で落ち着いたら、必ず次の未知を提示して再加速させる。

# 10. マイクロインタラクション要件

| トリガー | 必須反応 |
|---|---|
| 未知の土地へ到着 | 地図の霧が晴れる |
| 新しいテーマ発見 | 発見演出を出す |
| 新しい道発生 | 地図上に道を生成 |
| 意外な接続発見 | 接続線 / 演出を強調 |
| 長距離ジャンプ | 地図カメラが大きく移動 |
| 探索終了 | 次回への未踏地点を見せる |

演出は派手さではなく、**「世界が広がった」という意味が伝わること**を優先する。

---

# 11. 情報ページの要件

情報の本文を読む場合も、単純な「関連記事一覧」で終わらせない。

記事の最後に必ず、次の3種類を提示する。

- 深掘り
- 別の道
- 未踏の地

### 推奨見出し

> **この先、どの道へ？**

---

# 12. Bubble（情報の偏り）の可視化

ユーザー自身の探索傾向を、評価ではなく観測結果として見せる。

例:

```text
あなたの最近の探索

ゲーム       ████████████████
AI           ████████
音楽         ████
歴史         ██
科学         █
法律         ░
農業         ░
```

これにより、

> 「自分はどの領域ばかり見ているのか」

に気づける。

その後、

> **「まだ見ていない世界へ」**

という行動につなげる。

# 15. MVP受け入れ基準

以下を満たさない場合、MVP完成とはしない。

### A. 冒険感

- [ ] HOMEから未知が感じられる
- [ ] WORLDに未探索領域がある
- [ ] 常に次の探索先が見える
- [ ] 「戻る」以外の進行理由がある

### B. 好奇心

- [ ] 画面内に「予感」がある
- [ ] 情報到着後に次の疑問が発生する
- [ ] 遠景 / 霧 / ランドマークなどで未知を示唆する

### C. セレンディピティ

- [ ] 自分が選ばなかった領域へ進める
- [ ] 完全ランダムではない
- [ ] 「なぜそこへ来たのか」を確認できる
- [ ] 少なくとも1回はクロスドメインの発見を体験できる

### D. アハ体験

- [ ] 情報同士のつながりが説明される
- [ ] 新しい土地が開く
- [ ] 発見そのものに視覚的報酬がある

### E. 継続

- [ ] 5分後にも未探索領域が残っている
- [ ] 冒険記に探索経路が残る
- [ ] 次回の探索先を予告できる

---

# 16. 開発時に守る優先順位

仕様が衝突した場合は以下を優先する。

1. **好奇心を損なわないこと**
2. **未知への探索が自然に発生すること**
3. **発見した情報同士のつながりが理解できること**
4. **情報の偏りから外へ出られること**
5. **ファンタジー世界として気持ちよく見えること**
6. **ゲーム的なポイント / 育成等**

見た目より体験、数値報酬より発見、効率より探索を優先する。

# 17. Codexへの実装依頼

このドキュメントを基準仕様として、新規プロジェクトを構築する。

## 最初の実装タスク

1. HOME / WORLD / DISCOVERY / ADVENTURE LOG の4画面を作成
2. 固定テーマデータを投入
3. `ゲーム`を起点とする5分UXを再現
4. 世界地図の霧・未探索・道・ランドマークを実装
5. Discovery Eventを実装
6. 「なぜここに来たのか」のパス表示を実装
7. 「深く潜る / 横へ進む / 未踏の地へ」を実装
8. 冒険記に経路を保存
9. 5分シナリオを通しで確認できるデモモードを作る

## 実装上の注意

- まずUXを成立させる。巨大なデータ量を先に作らない。
- 「ファンタジーっぽいUI」を作ることが目標ではない。
- どの画面にも次の未知を残す。
- ランダム性は意味のある関連性と組み合わせる。
- すべての発見について、可能なら到達理由を説明可能にする。
- 1セッション内に最低1回、「え、なぜここにつながるの？」→「なるほど！」を発生させる。

# 18. 仕様変更ルール

今後仕様変更を行う場合、以下の質問にYesで答えられることを確認する。

> **その変更によって、ユーザーの好奇心・冒険心・未知への探索欲は強くなるか？**

Noの場合、原則として採用しない。

# 19. 設計上の一文

> **BubbleBreakerの世界では、発見した瞬間がゴールではない。発見したことで、さらに未知の世界が見えるようになる。**

これを本プロジェクトのUX原則として扱う。
